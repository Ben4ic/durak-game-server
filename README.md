# durak-game-server v2

## Что было не так (аудит 4 архивов)

- **durak-game-server (main)** — реально задеплоенный на Render бэкенд.
  `server.js` — только заглушка: комнаты в `const rooms = {}`, эндпоинт
  `/api/online/action` вообще ничего не делал (`res.json({ok:true})`).
  Игры как таковой на сервере не было.
- **Durak-Online-MVP-v1** — заброшенная попытка новой структуры
  (`rooms/`, `game/`, `storage/redis.js`). Но `game/engine.js` — пустой
  класс-заглушка (`start(){ this.state="playing" }`), `redis.js` не
  использовался нигде. По сути тоже пустой каркас.
- **durak-online-client (main)** и **durak-online-PVP-v2-render-fixed**
  — это один и тот же Next.js фронтенд (второй чуть новее, 3 файла
  отличаются). Оба проксируют `/api/online/*` на бэкенд через
  `lib/backendProxy.ts` → `GAME_SERVER_URL` (Render).

**Главная находка:** на фронтенде, в `lib/multiplayerDurak.ts`, уже
лежит полностью рабочий движок дурака (колода, козырь, атака/защита/
"бито"/"взять", подсчёт победителя, ревизии состояния) — просто он не
был подключён ни к какому реальному бэкенду. `app/online/game/[code]/
page.tsx` уже написан под его формат ответа (`publicOnlineState`) и
поллит `/api/online/room` каждые 500мс — то есть контракт клиент↔сервер
уже был спроектирован правильно, не хватало только настоящей
реализации на сервере.

## Что сделано в v2

Backend полностью переписан на реальную логику, эндпоинты **не
поменялись** — фронтенд трогать не нужно:

```
src/
 ├── server.js            — express-роуты, 1:1 повторяют старый контракт
 ├── rooms/roomManager.js — комнаты, токены игроков, TTL-очистка
 ├── game/engine.js       — движок дурака, портирован из lib/multiplayerDurak.ts
 └── websocket/socket.js  — необязательный WS push (Этап 3, задел на будущее)
```

- `/api/online/create|join|quick|leave|rejoin|public|room|action` — те
  же пути и тот же JSON-контракт, что ожидает текущий фронтенд.
- Комната теперь честно хранит **состояние игры** (колода, козырь, руки
  игроков, стол, кто атакует/защищается), а не просто список игроков.
- `/api/online/action` реально применяет ход через движок и отдаёт
  игроку **только его руку** (защита от подглядывания через сеть).
- WebSocket сервер поднят и рассылает `STATE_UPDATE`, но клиент пока
  им не пользуется (работает поллингом) — это задел под Этап 3, можно
  включить позже без переделки комнат/движка.

Проверено локально (без npm, чистой логикой): создание комнаты, join
второго игрока → игра стартует, атакующий делает ход → состояние и
revision обновляются корректно.

## Что осталось по плану из ТЗ (не сделано в этом заходе)

- **Redis** — `roomManager.js` спроектирован так, чтобы это было
  заменой одного модуля (сейчас `Map` в памяти процесса). Нужен, когда
  будет больше одного инстанса сервера/масштабирование.
- **PostgreSQL** (users/balance/transactions) — не трогали, в текущем
  контракте нет ставок/баланса.
- **Правила "подкидной для нескольких игроков"** (подкидывание чужими
  картами, "перевод") — движок сейчас 1v1 (ровно как во всех 4
  архивах), для 3+ игроков потребуется отдельная доработка.
- **Telegram Stars** — не в этом контракте.

## Запуск

```bash
npm install
cp .env.example .env
npm start
```

Задеплоить можно точно так же, как раньше (Render), просто заменив
содержимое репозитория `durak-game-server` на эту папку.
